Konsep Dasar

Apa itu Website Dinamis?

Website statis itu isinya tetep — yang lihat cuma kode HTML yang ditulis di file. Website dinamis bisa ngerjain sesuatu di belakang layar, nyimpen data, dan nampilin halaman yang beda buat user yang beda.

Website Statis

Seperti brosur cetak

Isinya sudah ditulis di file HTML. Setiap orang yang membuka halaman melihat hal yang sama persis. Nggak bisa nyimpen data dari pengunjung.

  • Nggak bisa simpan data user
  • Nggak ada login / register
  • Isi halaman tidak bisa berubah sendiri
  • Cocok buat: profil, portofolio, landing page
<!-- Isi file index.html --> <h1>Halo, Dunia!</h1> <p>Ini tulisan saya.</p> ← Semua orang lihat yang sama
Website Dinamis

Seperti aplikasi di web

Ada "otak" di server (PHP) yang bisa baca database, proses data, dan nyusun halaman sesuai siapa yang buka. Ini yang kita bikin hari ini.

  • Bisa simpan & baca data user
  • Bisa login, register, logout
  • Halaman bisa beda tiap user
  • Cocok buat: kasir, sistem absensi, dashboard
<?php echo "Halo, " . $_SESSION['username']; // ↑ Nama beda-beda tiap yang login ?>

Intinya: website dinamis = HTML (kerangka) + CSS (tampilan) + JavaScript (interaksi di browser) + PHP (otak di server) + MySQL (penyimpanan data). Tutorial ini bikin kelimanya lengkap.

Cara Kerja

Arsitektur Aplikasi Kita

Sebelum menulis kode, pahami dulu alur data di balik layar. Setiap kali kamu klik "Masuk", ada perjalanan yang terjadi.

Browser

User ngetik URL, isi form, klik tombol. Browser kirim permintaan HTTP ke server.

HTTP Request

Server (PHP)

Apache terima permintaan, jalankan PHP. PHP mikir: login? register? simpan?

SQL Query

Database (MySQL)

MySQL simpan & ambil data. Tabel users tempat akun kamu bersemayam.

Sesi (session) itu kunci login. Begitu PHP bilang "ini user yang benar", server nyimpen $_SESSION['user_id']. Setiap halaman berikutnya cek sesi itu — kalau ada, boleh masuk; kalau nggak, tendang balik ke login.

Persiapan
Kenapa langkah ini penting?

Banyak orang lompat langsung ke kode, lalu bingung kenapa muncul "Apache belum jalan". Siapkan dulu servernya — 10 menit di depan, hemat 2 jam di belakang.

Kita butuh tiga hal:

1XAMPP atau Laragon — paket berisi Apache (server web) + MySQL (database). Pilih salah satu, jangan dua-duanya.
2VS Code — editor kode. Gratis, ringan, dan punya fitur bagus buat PHP.
3Browser — Chrome atau Firefox versi terbaru.
Kerjakan sekarang

Buka XAMPP/Laragon → nyalakan Apache dan MySQL (harus hijau). Lalu buka http://localhost — kalau muncul halaman XAMPP/Laragon, berarti servermu hidup.

Bikin Database

Tabel users tempat akun bersemayam
MySQL
Kenapa database?

Kalau data akun cuma ditulis di HTML, dia hilang tiap halaman di-reload. Database bikin data permanen dan bisa dicari kapan pun.

Buka http://localhost/phpmyadmin, klik tab SQL, tempel kode ini, lalu klik Go.

SQL
Baca Kode Ini
1CREATE DATABASE IF NOT EXISTS — bikin database db_login. Kata IF NOT EXISTS biar nggak error kalau databasenya udah ada.
2USE db_login — pilih database ini sebagai target perintah berikutnya.
3CREATE TABLE users — bikin tabel dengan 5 kolom.
idINT AUTO_INCREMENT PRIMARY KEY — nomor urut otomatis, nggak boleh duplikat. Ini "KTP" tiap baris.
usernameVARCHAR(50) NOT NULL UNIQUE — maksimal 50 huruf, wajib diisi, nggak boleh sama dengan yang lain.
emailSama seperti username, tapi maksimal 100 huruf.
passwordVARCHAR(255) — sengaja lebih panjang dari yang kamu kira, karena hasil password_hash() itu sekitar 60-255 karakter.
created_atTIMESTAMP DEFAULT CURRENT_TIMESTAMP — otomatis diisi waktu dibuat. Kamu nggak perlu ngetik tanggal.

Bikin Jembatan Database

File koneksi.php — dipakai semua halaman
PHP + MySQL
Kenapa file terpisah?

Kalau alamat server & password database ditulis di tiap halaman, bayangin kalau passwordnya ganti — kamu harus edit 5 file. Dengan file koneksi.php, kamu cuma edit satu tempat.

Bikin file koneksi.php di folder proyek, isi dengan:

PHP
Baca Kode Ini
$hostAlamat server database. localhost artinya database ada di komputer yang sama.
$userUser database. Default XAMPP/Laragon adalah root.
$passPassword database. Default XAMPP/Laragon kosong — makanya tanda ''.
$dbNama database yang kita buat di Tahap 2: db_login.
new mysqliIni cara PHP nyambung ke MySQL. mysqli itu library bawaan PHP — nggak perlu install apa-apa.
connect_errorKalau koneksi gagal, kita hentikan program dan kasih pesan. Ini mencegah error aneh yang susah dibaca.
set_charsetPakai UTF-8 supaya huruf Indonesia (seperti é atau ç) nggak jadi karakter aneh di database.
Coba sekarang

Bikin file tes.php isinya <?php include 'koneksi.php'; echo "Koneksi OK!"; ?>, lalu buka http://localhost/proyek/tes.php. Kalau muncul "Koneksi OK!", jembatanmu sudah tersambung.

Halaman Register

Form daftar + simpan ke database
PHP + Form
Apa yang terjadi di balik layar?

User isi form → browser kirim data ke server → PHP validasi dulu → cek apakah username/email sudah dipakai → hash password → simpan ke database → alihkan ke halaman login.

Bikin file register.php, isi dengan kode lengkap ini:

PHP + HTML
Baca Kode Ini — Bagian PHP
1session_start() — wajib dipanggil di awal kalau mau pakai $_SESSION.
2include 'koneksi.php' — "masukkan" jembatan database ke halaman ini.
3$_SERVER['REQUEST_METHOD'] === 'POST' — cek apakah form baru disubmit. Kalau belum, halaman cuma nampilin form kosong.
4trim() — buang spasi di depan/belakang. ?? '' — kalau kolomnya kosong, pakai string kosong (biar nggak error).
5Validasi — cek kolom kosong, format email, dan panjang password sebelum menyentuh database.
6prepare() + bind_param() — wajib pakai ini. Ini yang bikin kamu kebal dari SQL Injection. Simbol ? itu "tempat pati" yang isinya diganti variabel.
7password_hash() — ubah password jadi teks acak yang nggak bisa dibalik. Jangan pernah simpan password asli!
8header('Location: ...') — alihkan browser ke halaman lain. exit wajib dipanggil setelahnya, kalau nggak kode di bawahnya tetap jalan.
9htmlspecialchars() — ubah < jadi &lt; supaya pesan error nggak bisa disisipi kode berbahaya (XSS).
Alur yang benar

1. Buka http://localhost/proyek/register.php
2. Isi username, email, password → klik Daftar
3. Muncul pesan "Registrasi berhasil! Silakan login."
4. Kamu diarahkan ke login.php

Coba sekarang

Daftar pakai username yang sama dua kali. Percobaan kedua harusnya muncul pesan "Username atau email sudah terdaftar." — itu bukti validasi di langkah 3 bekerja.

Halaman Login

Cek akun + bikin sesi
PHP + Session
Bedanya login sama register?

Register menambah data. Login mencari data yang sudah ada, lalu membuktikan bahwa kamu benar pemiliknya lewat password.

Bikin file login.php:

PHP + HTML
Baca Kode Ini
flash$_SESSION['flash'] itu pesan sekali pakai dari halaman register. Kita unset() setelah dibaca, biar nggak muncul terus.
prepareCari user berdasarkan username atau email — makanya WHERE username = ? OR email = ? dan bind_param("ss", $user, $user) dipakai dua kali.
fetch_assocAmbil satu baris hasil sebagai array. Kalau nggak ada baris, $row akan null.
password_verifyIni kebalikan dari password_hash(). Dia cek apakah password yang diketik sama dengan hash di database. Nggak bisa membalik hash — makanya aman.
$_SESSIONSetelah cocok, kita simpan user_id dan username ke sesi. Inilah yang bikin halaman lain tahu "ini dia yang login".
errorSengaja nggak disebutin apakah username atau password yang salah — biar orang jahat nggak bisa menebak username yang terdaftar.
Yang harusnya terjadi

Username & password benar → masuk dashboard.php
Salah satu salah → "Username atau password salah."

Dashboard (Halaman Terproteksi)

Cuma bisa dibuka kalau sudah login
Session
Kenapa perlu proteksi?

Kalau dashboard bisa dibuka siapa saja, login jadi nggak guna. Proteksi itu baris pertama di tiap halaman terproteksi: cek sesi, kalau nggak ada — tendang balik ke login.

Bikin file dashboard.php:

PHP + HTML
Baca Kode Ini
1isset($_SESSION['user_id']) — cek apakah sesi login ada. Kalau nggak, header() lempar user ke login.php.
2htmlspecialchars($_SESSION['username']) — wajib! Kalau username mengandung <script>, ini mengubahnya jadi teks biasa.
3(int) $_SESSION['user_id'] — paksa jadi angka. Ini mencegah data aneh masuk ke halaman.
4date('d-m-Y H:i:s') — fungsi bawaan PHP buat tampilin tanggal & jam sekarang.
Coba sekarang

Buka http://localhost/proyek/dashboard.php tanpa login dulu. Kamu harusnya langsung dilempar ke login.php. Itu bukti proteksinya jalan.

Logout

Hancurkan sesi dengan benar
Session
Kenapa nggak cukup session_destroy() saja?

Ada dua hal yang perlu dibersihkan: data sesi di server, dan cookie sesi di browser. Kalau cookie nggak dihapus, browser masih menyimpan "kunci" lama — dan itu bahaya kalau komputernya dipakai orang lain.

Bikin file logout.php:

PHP
Baca Kode Ini
1$_SESSION = [] — kosongkan semua data sesi. Ini langkah pertama.
2session_get_cookie_params() — ambil setting cookie sesi (path, domain, dll) supaya kita bisa hapus cookie yang persis sama.
3setcookie(..., time() - 42000) — set waktu kedaluwarsa cookie jadi 42000 detik yang lalu. Browser langsung menghapusnya.
4session_destroy() — hapus file sesi di server.
5header('Location: login.php') — kembali ke halaman login.

Bikin file style.css:

CSS
Baca Kode Ini
bodydisplay:flex + align-items:center + justify-content:center + min-height:100vh — trik buat tengahkan kartu di tengah layar secara vertikal & horizontal.

Keamanan — Wajib Baca!

Empat hal yang memisahkan kode aman dan kode berbahaya
Penting
Ini bukan opsional.

Kebanyakan website siswa bocor bukan karena diserang hacker canggih — tapi karena empat hal ini dilewatkan. Baca baik-baik.

1. Password — pakai password_hash(), bukan md5()
Salahmd5($password) — nggak aman. md5 bisa dibalik pakai tabel pelangi di internet. Kalau database bocor, semua password ketemu aslinya dalam hitungan menit.
Benarpassword_hash($password, PASSWORD_DEFAULT) — pakai algoritma bcrypt yang otomatis di-update PHP tiap versi. Dia juga menambahkan "garam" (salt) acak, jadi dua orang dengan password sama punya hash beda.
CatatanUntuk login, pakai password_verify(). Jangan pernah mencoba "membalik" hash — memang nggak bisa.
2. SQL — pakai prepare(), jangan "SELECT * FROM users WHERE username = '$user'"
SalahKalau kamu nyambungin input user langsung ke query, seseorang bisa mengetik ' OR '1'='1 di kolom username — dan masuk tanpa password. Ini namanya SQL Injection.
Benarprepare() + bind_param() memperlakukan input user sebagai data biasa, bukan bagian dari perintah SQL. Mustahil disusupi.
AturanAturan praktis: kalau ada input user di query, wajib prepare(). Nggak ada kecuali.
3. Output — pakai htmlspecialchars() saat menampilkan data user
SalahKalau username <script>alert('hacked')</script> ditampilkan apa adanya, script itu jalan di browser orang lain. Namanya XSS (Cross-Site Scripting).
Benarhtmlspecialchars() mengubah < jadi &lt; — script-nya jadi teks biasa yang cuma ditampilkan, bukan dijalankan.
AturanAturan praktis: setiap data dari user/database yang ditampilkan di HTML, bungkus dengan htmlspecialchars().
4. Sesi — jangan simpan password di session
Salah$_SESSION['password'] = $pass; — kalau file sesi bocor, password ikut bocor.
BenarSimpan cuma user_id dan username. Password cuma diverifikasi sekali saat login, lalu dibuang.
AturanSesi simpan di server, cookie cuma simpan ID sesi. Itu desain yang benar.
Checklist sebelum disebut "selesai"

Password pakai password_hash()
Semua query pakai prepare()
Semua output pakai htmlspecialchars()
Sesi cuma simpan user_id & username
Halaman terproteksi punya cek sesi di baris pertama

Troubleshooting

Masih Error? Ini Jawabannya

90% masalah yang kamu hadapi pasti ada di sini. Cari gejalanya, temukan solusinya.

Penyebab: port 80 (Apache) atau 3306 (MySQL) sudah dipakai program lain — biasanya Skype, VMware, atau XAMPP sebelumnya yang nggak mati total.

Solusi:
1. Buka XAMPP → netstat atau cek httpd.conf, ganti port 80 jadi 8080.
2. Atau matikan program yang pakai port itu.
3. Kalau pakai Laragon, klik kanan icon Laragon → Restart All.
4. Cek di terminal: netstat -ano | grep :80 untuk lihat siapa yang pakai.
Penyebab: file style.css nggak kebaca — biasanya karena nama file salah, lokasi salah, atau href-nya nggak sesuai.

Solusi:
1. Pastikan file namanya style.css (huruf kecil semua).
2. Pastikan dia satu folder dengan login.php.
3. Cek di browser: tekan F12 → tab Network → reload. Kalau style.css berwarna merah / 404, berarti path-nya salah.
Penyebab: file koneksi.php nggak berhasil di-include, atau namanya salah ketik.

Solusi:
1. Cek baris include 'koneksi.php'; — pastikan nama file dan folder sama persis.
2. Coba ganti jadi include __DIR__ . '/koneksi.php'; — ini cara paling aman.
3. Pastikan koneksi.php ada di folder yang sama dengan halaman yang memanggilnya.
Penyebab: PHP versi kamu terlalu lama. password_hash() baru ada di PHP 5.5+.

Solusi:
1. Cek versi PHP: buat file info.php isinya <?php phpinfo(); ?>, lalu buka di browser.
2. Kalau di bawah 5.5, update XAMPP/Laragon ke versi terbaru.
3. XAMPP modern (PHP 8.x) pasti punya fungsi ini.
Penyebab: session_start() nggak dipanggil di dashboard, atau sesi nggak sempat kesimpan.

Solusi:
1. Pastikan session_start() ada di baris pertama dashboard.php, sebelum output apa pun (termasuk spasi/enter).
2. Jangan ada echo/print/HTML sebelum session_start().
3. Cek di browser: F12 → Application → Cookies → pastikan ada cookie PHPSESSID.
Penyebab: Ada output (teks, spasi, atau HTML) sebelum header() atau session_start(). PHP nggak bisa kirim header kalau halaman sudah mulai "dicetak".

Solusi:
1. Cari spasi atau enter di atas <?php — hapus semua.
2. Jangan ada echo sebelum header().
3. Kalau pakai include, pastikan file yang di-include nggak punya spasi di awal/akhir.
Penyebab: Kamu membuka file lewat file://, bukan http://localhost. PHP cuma jalan lewat server.

Solusi:
1. Pastikan Apache sudah menyala.
2. Buka lewat http://localhost/proyek/login.php.
3. Jangan dobel-klik file PHP di folder — itu buka lewat file://.
Penyebab: db.sql belum dijalankan, atau namanya beda dengan yang ditulis di koneksi.php.

Solusi:
1. Buka http://localhost/phpmyadmin.
2. Pastikan ada database db_login di daftar sebelah kiri.
3. Kalau belum ada, klik tab SQL, tempel db.sql, klik Go.
4. Cek lagi di koneksi.php: $db = 'db_login'; harus sama.
Tips:
1. Baca baris pertamanya — di situ letak masalahnya.
2. Catat nomor baris yang disebut (contoh: on line 23).
3. Cari kata kuncinya di Google, tambahkan "PHP" di belakang.
4. Aktifkan error lengkap sementara: tambahkan di atas file: error_reporting(E_ALL); ini_set('display_errors', 1);
5. Ingat: pesan error itu menunjukmu ke jalan
